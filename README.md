**opic-website is the official website of the OPIC open intelligent compute platform**: a Docusaurus 3 site that publishes the platform introduction, overall architecture, the 23 capability domains, the ontology engineering method, security and compliance, metering and operations methodology, industry benchmarks, technology-selection assessments, and the implementation roadmap.

The website answers a recurring question from evaluators and partners: what exactly is OPIC, and how is it built? Every page traces back to a frozen fact source — the OPIC requirements baseline v3.2 (the `review/` directory and each center's `spec/` in the `opic-design` repository), aligned with the version-freeze baseline document 110. The site introduces no commitments beyond that baseline.

This repository contains the Docusaurus site (classic preset), the documentation tree, the blog, and the homepage.

## Architecture

opic-website runs as a static site generated by Docusaurus 3:

- **Docusaurus core + classic preset** (`@docusaurus/core` / `@docusaurus/preset-classic` 3.7) — docs, blog, and pages plugins with the classic theme; `prism-react-renderer` for syntax highlighting.
- **`docs/`** — the documentation tree: the nine platform pages, the `deploy/` series, and the `techbase/` series (each with a `_category_.json` for sidebar ordering).
- **`blog/`** — release announcements and technical assessments.
- **`src/pages/index.js`** — the homepage: feature cards plus platform statistics.
- **`static/`** — static assets served as-is.

Build path: Markdown / MDX under `docs/` and `blog/` → Docusaurus build → static bundle under `build/` → any static host or the platform's own ingress.

Engineering practices follow the [Project-HAMi/website](https://github.com/Project-HAMi/website) conventions: Node 20+, the classic preset, i18n directory conventions, and markdownlint / prettier tooling.

## How opic-website Relates to Other Tools

opic-website is a **publication surface**, not a fact source. It republishes frozen baselines; it does not author new commitments.

| Layer | Tools | Relationship |
|---|---|---|
| Fact source | `opic-design` repository (requirements baseline v3.2) | All content traces to the `review/` directory and each center's `spec/`; the version-freeze baseline document 110 is the alignment anchor |

| Engineering reference | [Project-HAMi/website](https://github.com/Project-HAMi/website) | Engineering conventions: Node 20+, classic preset, i18n layout, markdownlint / prettier |

## Usage

### Local Development

Prerequisites: Node.js 20 or later.

```bash
npm install
npm start          # dev server → http://localhost:3000
npm run build      # output in build/
npm run serve      # preview the build output locally
```

### Content Structure

- `docs/` — platform introduction / overall architecture / 23 capability domains / ontology method / security and compliance / metering and operations methodology / industry benchmark / technology selection / roadmap
- `blog/` — release announcements and technical assessments (first post: the requirements baseline v3.2 freeze)
- `src/pages/index.js` — homepage (feature cards + platform statistics)

### Content Fact Source

All content is taken from the OPIC requirements baseline v3.2 deliverables (the `review/` directory and each center's `spec/` in the `opic-design` repository), aligned with the version-freeze baseline document 110. This site introduces no commitments beyond that baseline.

### Internationalization

The framework has the i18n directory conventions reserved (referencing HAMi: `defaultLocale` + `i18n/<locale>/`). The first release enables `zh-Hans` only; English is enabled on demand.

## Deployment

The site builds to a static bundle and can be served by any static host:

```bash
npm ci
npm run build      # → build/
```

Serve `build/` behind the platform ingress, or publish it to any static hosting. For the platform's own production topology, see the [production deployment plan](docs/deploy/prod-deployment-plan.md).

## Contributing

Before opening a pull request, please confirm:

1. `npm run build` passes with no broken links.
2. Any new page traces to a frozen fact source (the v3.2 baseline or a named repository document); no commitments beyond the baseline.
3. New docs declare their `sidebar_position` and, for the `deploy/` and `techbase/` series, keep the mirrored structure of their source repositories.
4. Markdown passes the markdownlint / prettier checks.

Branch names and commit messages follow `feat|fix|docs|chore(scope): summary`.

## Roadmap

This repository does not maintain a long-range feature roadmap. Planned work and progress are tracked in the open:

- **Recently completed**: the first release (2026-09-28) with the nine platform pages, the deployment and techbase doc series, and the homepage.
- **Known gaps**: the English locale is reserved but not yet enabled; additional benchmark refreshes follow the baseline refresh cadence.
- **Limitations**: this site republishes frozen baselines — it is not the fact source itself; authoritative content lives in the `opic-design` repository and each center's specifications.
